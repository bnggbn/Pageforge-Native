# 分層保存、VAX 完整性與大型文件（規劃）

本文件補充 [版本儲存](VERSION_STORAGE.md) 與 [草稿復原](DRAFT_RECOVERY.md)。新匯入書已有正文物件樹、獨立筆記 blob 及去重讀寫，見 [內容物件架構](CONTENT_OBJECTS.md)。編輯已接固定範圍的分節替換模型；操作日誌、局部操作式後端、root 型正式 VAX、全文件選取／undo 及可視區閱讀仍待實作；不直接提高上限，也不改寫既有 VAX 歷史。

## 保存分層

| 層次 | 保存時機 | 資料與用途 | 是否追加正式 VAX |
| --- | --- | --- | --- |
| 編輯工作區 | 每次輸入 | 記憶體中的文字模型、游標與尚未落盤操作 | 否 |
| 草稿復原 | 停筆，或持續輸入達最大等待；離開時 flush | 可驗證操作日誌及 checkpoint，恢復至最後成功同步點 | 否 |
| 正式版本 | 明確保存文字、保存／刪除筆記、還原或採用版本 | 不可變文件狀態及連續 VAX 事件 | 是 |

checkpoint 是復原或讀取基準，不代表正式版本。定時保存不得呼叫正式 commit API；正式保存則以指定的已確認草稿 sequence 為輸入，不能意外包含保存期間新輸入的內容。發布失敗保留草稿，成功後才確認基準切換；舊復原資料仍須遵守引用及保留期。

## 現在是全文儲存嗎

舊書仍是每個 revision JSON 包含完整 content 與 notes；只新增筆記也會重複正文。新匯入書預設為 objects-v1：版本只保存 metadata 與正文／筆記 root，未變物件共用。草稿仍保存完整文字，API 仍傳目前全文；冷讀取仍完整驗證歷史，新格式每次只讀／驗一次相同物件；一般 Load／Commit 逐 root 串流正文雜湊、逐版筆記驗證後釋放，只還原指定快照。完整歷史稽核另用 LoadHistory／CommitHistory，legacy 仍完整解碼。筆記陣列仍為整包 blob，累加時有 O(N²) 實體成長，physical 歷史容量限制仍可能擋住保存。

VAX envelope 本身不放全文，它記錄正文、筆記及視圖的雜湊與版本資訊。目前 contentHash 是完整原文 UTF-8 位元組的 SHA-256；notesHash 是完整 notes 的既有 canonical bytes 雜湊。SAI 以協定 domain、前一 SAI 及 canonical envelope 雜湊計算，需維持 vax-sdk 1.0.0 的編碼及兩階段雜湊。

## 分層完整性

復原日誌每筆包含 schema、document／draft／generation、連續 sequence、前一紀錄雜湊、基準識別、操作負載與長度。紀錄雜湊覆蓋上述欄位，採明確且版本化的編碼及 domain；初筆綁定已驗證 checkpoint。重播先驗證序號、父雜湊及操作的基準／範圍，再依順序套用。正常追加只雜湊本筆有界操作，不能每兩秒重新 canonical 化或雜湊幾百萬字全文。checkpoint 另保存可驗證的完整狀態承諾；重開及發布時仍須驗證實際還原內容。

復原鏈可偵測相對於可信基準的損壞、亂序或缺漏；它不進正式 VAX，亦不是對外公證。正式發布才產生 VAX 節點，綁定前一 SAI 與內容承諾。現有本機鏈沒有簽章或外部可信 head：若歷史與 head 一起被替換，單靠雜湊鏈無法證明沒有整鏈重寫或有效尾端截斷。若未來需要此保證，須另外設計在寫入者控制之外的可信 head／簽章保管；普通同目錄副本不提供此信任。

## 大型文字的實體儲存與輸入

1. 正文與筆記分開，以不可變、內容定址的分塊物件保存；版本保存有順序的區塊樹／manifest，未變區塊共用。checkpoint 可是完整樹根及其可達物件，不必重寫整文。候選區塊大小 32–64 KiB，正式選擇前量測；不得切斷 UTF-8 字元。
2. 編輯工作區使用 piece table／rope 類型的文件模型，輸入端提供位置、刪除範圍及新增文字等有基準的操作。Go 檢查 sequence、範圍、字元邊界、容量與衝突後套用。若仍每次傳全文再算 diff，就仍有整文複製、傳輸與比較成本。IME 組字、撤銷／重做及貼上亦須驗收。
3. 區塊樹要承諾內容、次序及長度；葉與內部節點雜湊使用不同 domain，格式與演算法有版本。穩定分段／平衡樹只更新改動區塊及祖先路徑；避免按全文固定偏移重切，否則文首插字可能改變後面所有區塊。可借用 [RFC 9162 的 Merkle 樹原則](https://www.rfc-editor.org/rfc/rfc9162.html#section-2.1)，但可編輯文件樹並非該 RFC 的 append-only log，也不宣稱協定相容。
4. 平衡及穩定分塊下，小修改的雜湊工作可接近改動位元組加樹高；初次驗證、全文匯出及完整搜尋仍可能掃描全文。不能只憑 Merkle 名稱就宣稱所有操作固定成本。增量壓縮僅在有收益時採用，保持有界還原深度；GC 必須保留正式版本、分支、草稿與復原索引可達物件。
5. 大檔閱讀／編輯需分段排版、按需載入與背景解析；邏輯選取範圍由全文模型持有，保留跨段落選取、全選及複製，不能回到獨立 Widget 各自截斷選取。diff 先定位變動區塊，再按需比較與顯示；不能單純解除現有全文 diff 上限。

## 與既有 VAX 的相容界線

第一步只改實體儲存：依區塊順序精確還原，正式發布／首次驗證仍串流計算完整 UTF-8 SHA-256，保持既有 contentHash、notesHash、SAI 與事件 ID。這仍有一次 O(正文大小) 的正文雜湊成本，應在 Go 執行，不能算成只雜湊差異。未變正文可在已驗證、不可變且基準可信的情況共用既有結果；不能拿未驗證快取取代完整性檢查。

復原層與內容索引可另外使用帶演算法標籤的樹根；Merkle root 不等於現有 SHA-256(fullText)。若以後要讓正式發布也只更新區塊雜湊，需新增 Pageforge 事件內容合約版本及其 ordered chunk root 承諾，保留舊版解碼／驗證並制定 migration。可沿用 SAI 鏈結原語，但不能默默把 v1 contentHash 的值換成樹根，亦不得改寫舊鏈。歷史摘要、按需驗證與可信 head 的信任合約需一起設計；單改儲存格式不會消除所有歷史驗證成本。

## ID、筆記與多人多機

穩定物件 ID 與內容 hash 分工；ID 到內容的映射由樹根承諾。來源正文與個人的筆記／牆分別演進，個人事件綁定自己的 notesRoot／wallRoot 與指定正文版本參照；不把所有讀者的私人筆記塞進來源書版本。來源 VAX 鏈與版本 DAG 分開，同 owner 多機並行修改另開鏈保留副本及簽章見 [識別與同步合約](IDENTITY_SYNC.md)。跨 owner 預設分享快照及建立獨立副本，整面牆含布局與紅線，見 [分享合約](WALL_SHARING.md)。目前尚未實作多人功能。

## 幾百萬字目前會怎樣

| 項目 | 目前限制／結果 |
| --- | --- |
| 文字匯入、編輯及草稿 | limits.textMiB = 5，計算 UTF-8 位元組，不是字數 |
| 100 萬個一般中文字 | 約 2.86 MiB，未超文字容量，但未驗收此規模的閱讀／編輯效能 |
| 300 萬個一般中文字 | 9,000,000 bytes，約 8.58 MiB，超過預設容量而拒絕 |
| 放寬文字限制後的 100 個上述全文版本 | 僅正文約 858 MiB，未計 notes／JSON；現有 256 MiB 歷史總量限制會先阻擋載入 |
| 全文 diff | 前後兩文合計最多 1,048,576 個 UTF-16 code units，且有時間上限 |
| 目前 Flutter 編輯／閱讀 | 編輯為可配置分節 TextField／替換表，保存時才組回全文；閱讀仍全文 Markdown 排版。沒有整體百萬字體驗保證 |

字數換算只針對一般 3-byte 中文字元；ASCII、emoji、混合文字及 JSON 轉義成本不同。上述為容量算術，並非大檔實測結果。

初步隔離量測與現有瓶頸見 [大型文件現況基準](experiments/LARGE_DOCUMENT_BASELINE.md)。原基準提交只增加 opt-in 探針；後續已完成新書的物件儲存第一階段，本輪完成編輯的分節排版與按鍵替換表，閱讀可視區及完整 UI 大檔驗收仍未完成。新舊格式對照見 [物件儲存基準](experiments/CONTENT_OBJECTS.md)。

## 實作順序與驗收

依 [review 補量測](experiments/REVIEW_FOLLOWUP.md) 調整順序：先處理 UI 分段編輯與保留邏輯選取的可視區閱讀排版／分章 API，同時移除一般 Book 的歷史全文常駐。接著補持續輸入最大保存等待、個別筆記物件／有序索引、舊書遷移、失效鎖與壞 manifest 隔離。在目前有界範圍內草稿仍可暫用全文 checkpoint；局部樹更新、操作日誌與 root 型事件另行量測及驗收。完成大型閱讀器、編輯器、diff 與冷驗證量測後，才分級放寬容量；root 型正式事件屬後續獨立合約改版。

用隔離合成書庫驗收 100／300／500 萬字的中英混合、emoji、換行及非高度重複內容；測量小修改、文首插入、大段貼上、筆記版本共用正文、100 版讀取及切版。記錄輸入 p95 延遲、峰值記憶體、傳輸量、實體磁碟成長、冷／暖讀取與驗證耗時。故障測試涵蓋改動／缺失／重排區塊、錯誤基準、日誌斷裂、checkpoint 各發布階段 crash、舊協定精確往返及跨段落／全文選取；不得以單一重複字元的壓縮率代表真實文件。
