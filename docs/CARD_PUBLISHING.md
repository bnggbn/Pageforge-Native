# 發布卡片（規劃）

發布卡片是獨立功能，不必先分享整面牆。沿用 [分享與來源合約](WALL_SHARING.md)；目前沒有發布介面、分享包或傳送服務，以下為接續實作規格。

## 操作與內容

卡片選單提供「發布卡片」：選擇已保存的指定版本，預覽分享內容後發布不可變快照。未保存的草稿先提示保存；發布不在每次輸入時自動進 VAX，也不把後續修改偷偷套入先前發布物。

單卡快照包括筆記內容、標題（若有）、原文引用、來源文件／版本／位置、原作者及這次發布者。預設不附私人紅線、主題、其他卡片、整面布局、草稿或完整歷史。多人提供卡片不授予對方修改自己牆的權限；整面發布另走完整牆流程。

第一階段使用可匯出／匯入的分享包，供使用者自行傳送；「發布」不等於自動上傳到公開網站。遠端公開或限對象傳送需另做目的地、可見性、認證與讀取權限；沒有實作的目的地不能在介面假裝可用。

發布成功後在「已發布卡片」查看快照版本與來源。後續修改草稿不改已發布 bytes；再次發布產生新版本，舊版仍可辨識。停止提供未來下載不能收回對方已接收的副本，介面不承諾遠端抹除。

## 識別、VAX 與接收

同一發布系列有 publishedCardId，每次發布另有 publishedRevisionId／bundleId／bundleRoot，並承諾指定來源 noteId／revision／內容 hash、作者來源、發布者及 schema。發布系列不是收件者的本地 noteId 或 cardInstanceId；各種 ID 的 namespace 與映射必須有型別。

建立發布快照的正式操作追加一次 Pageforge 發布事件，承諾發布 ID、來源版本與 bundleRoot；依新合約驗證，不改寫 legacy VAX 的 kind 或 canonical bytes。發布證明與作者認證界線沿用分享合約，不能把未認證的原作者欄位說成已證明身分。

接收先驗證並預覽，讓使用者挑選自己的主題；生成本地 noteId／cardInstanceId，保存不可變來源參照及映射。相同卡片發布版本的重送冪等；明確選「再建立一份」才另產副本。同內容不同身分不以 hash 自動合併；缺來源書仍能看引用，原文跳轉標示未取得來源。

接收的新卡片預設不帶對方的紅線，也不更改既有卡片或布局。接收後可自己寫筆記、移動、連紅線；自己的修改形成自己的歷史，不回寫發布者。

來源有新發布版本時顯示「有新版卡片」，不打斷閱讀或編輯。預設先保留為另一張候選卡片；使用者可稍後比較、加入或明確選用整張新版。即使自己的副本已有修改，也不跳出必須解決的逐欄位 conflict；原版與本地版均保留，不用 timestamp 覆蓋。

## 持久化與驗收

Go 管理有界分享包與發布索引，Flutter 透過 repository／專用 ViewModel 操作。先保存並驗證不可變物件，再發布可達索引；重試不重複產生發布事件，失敗保留原卡片。發布與接收的操作 ID／冪等記錄、容量配置、索引中斷復原及新事件 migration 需在實作前定義，不能直接套用現行布局 API。

驗收包含：只分享選定卡片與版本、不夾帶私人內容、發布中繼續輸入、舊發布不可變、重試／重送冪等、未認證舊作者、缺來源書、接收至選定主題、接收後獨立修改／連線、來源更新不覆寫本地版、損壞／超限／中斷不產生半份發布，以及卡片與整牆來源合約一致。
