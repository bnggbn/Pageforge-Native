# 定時增量草稿復原（規劃）

## 目的與目前狀態

意外 crash 後，讓使用者找回最後成功落盤的文字與筆記草稿，再自行決定續寫或保存為正式版本。定時復原資料獨立於正式 VAX 歷史，持續編輯不會自動產生大量正式版本。

目前實作是停筆後依 reading.draftDebounceMs（預設 500 ms）保存完整 draft JSON，Go 先寫暫存檔並 Sync，再原子替換；重開會載入已保存草稿。持續輸入會重設防抖計時，因此仍可能有較長一段修改未落盤。定時最大等待、增量日誌與復原選擇介面尚未實作；以下是接續實作的驗收合約。

## 保存排程

- 同時使用停筆防抖與最大等待：停筆 500 ms 儘快保存；持續輸入時，自首次尚未保存的修改起，目標每 2 秒送出最新狀態。計時器不得因每次按鍵重新開始最大等待。
- 未改動時不寫磁碟；輸入期間只更新記憶體。由 focused working-copy persistence 控制排程，Widget 與 Go 版本提交邏輯維持各自職責。
- 每份草稿最多一個保存請求在途。期間的新修改合併成最新待保存狀態，完成後繼續保存；不排隊保存每個過時文字副本。
- Go 成功同步復原紀錄後才回覆 durable sequence，Dart 僅將該次實際落盤狀態標示已保存。失敗保留本機輸入及待保存狀態，顯示錯誤並有界退避重試。
- 正常離開、關閉及手動保存仍執行 flush；2 秒是健康服務下的排程目標，I/O、請求或系統停頓可能延長。保證可恢復至最後成功落盤點，不能保證 crash 前的最後一個按鍵。

## 完整基準與增量日誌

復原單位是 document ID + draft ID + generation，紀錄完整基準 checkpoint 及其後的增量。每一 generation 保持自己的 baseRevisionId，換基準或衝突另存草稿時開新 generation，不能把兩條草稿的增量混在一起。

- 初始保存建立完整 checkpoint，包含 content／body／quote／location。之後增量保存這些草稿欄位的變更；Markdown／TXT 可含正文，PDF／EPUB／XLSX 則包含其可編輯的筆記草稿。正式 notes 與布局仍使用各自持久化合約。
- Go 負責驗證與持久化可精確往返的儲存增量。大型文件由編輯模型提供有基準的操作，避免定時傳全文後重新算 diff；小型 legacy 草稿可先維持完整傳輸。UI 顯示用 diff 有時間及長度限制，不能作為唯一恢復資料。UTF-8 位元組偏移需檢查字元邊界，驗收中文、emoji、合成字元、空行與檔尾換行。
- 每筆紀錄包含 schema version、document／draft／generation、連續 sequence、前一紀錄雜湊、基準識別、操作負載與長度；紀錄雜湊覆蓋這些欄位，初筆綁定已驗證 checkpoint。checkpoint 保存完整狀態承諾，重播驗證實際內容；若採區塊樹根需另帶演算法標籤。不得為每筆高頻紀錄重新雜湊全文。相同 sequence 的重試須冪等；不同內容、過期 token 或錯誤基準須拒絕，不能覆蓋另一份草稿。
- 增量無收益、達到還原深度或容量門檻時，改寫新的完整 checkpoint。初期候選深度為 16；單紀錄、日誌總量、還原後內容與 replay 工作量均需設上限。
- 追加紀錄後 Sync 才確認保存。新 checkpoint 先寫暫存檔、同步及驗證，再原子發布 generation 索引；舊 checkpoint／日誌至少保留至新索引發布成功且可重開驗證。Windows 的發布順序需用崩潰注入實測。
- 原本 draft JSON 及其讀取器保留，先以增量日誌作附加復原資料，驗證與遷移完成後才考慮替代完整草稿寫入。正式 original、versions 與 VAX canonical bytes 不改寫。

checkpoint 與復原紀錄不追加正式 VAX；分層完整性、區塊儲存及百萬字文件的相容界線見 [大型文件規劃](LARGE_DOCUMENTS.md)。

增量減少重複落盤內容；保存期限來自排程，完整快照也可以做到。實作順序先補最大等待與請求合併，再接可驗證日誌，最後評估壓縮／去重收益。

## 重開與損壞處理

1. 先載入最後有效 checkpoint，依連續 sequence 驗證並還原紀錄，取得最後成功同步的狀態。
2. 尾端寫到一半、checksum 錯誤或 sequence 中斷時，停在最後有效紀錄。保留原始日誌及異常資訊；不跳過中間損壞繼續套用後續差異，不自動刪除可能可救的資料。
3. 若還原狀態比普通 draft JSON 更新，提供「找到意外中斷前的草稿」：顯示時間、來源、可恢復範圍與內容預覽，讓使用者選擇續寫或明確捨棄。捨棄只處理指定草稿 generation。
4. 若正式 head 已變，保留原基準並另存可比較草稿，不能直接套到新的正文。將復原內容建立正式 VAX 版本需使用者明確保存。
5. Flutter crash 的父程序管線關閉已有 sidecar 收尾機制；Go 也被強制終止時可能留下 server.lock。啟動恢復需能確認鎖持有程序已死亡，且防止 PID 重用誤判，才容許回收自己的失效鎖；活躍持有者仍拒絕第二個 writer。

## 配置與驗收

以下名稱與數值是候選配置，尚未加入 runtime config；實作時需補 Go 驗證、合理上下界及舊設定預設：

| 配置 | 候選預設 | 用途 |
| --- | --- | --- |
| reading.draftMaxWaitMs | 2000 | 持續編輯的最大排程等待 |
| recovery.enabled | true | 定時增量復原資料 |
| recovery.maxReplayDepth | 16 | checkpoint 間最大增量深度 |
| recovery.journalMiB | 32 | 每份草稿日誌容量；超量先 checkpoint，不丟待保存內容 |
| recovery.retainedGenerations | 2 | 保留可回退的完整 generation 數 |

現有文字、筆記、working copy 數量及 JSON 讀取容量限制繼續適用。接近限額時優先保留最後可驗證狀態並呈現錯誤；不得默默清空復原日誌。正式發布後，GC 只能移除未被草稿／復原索引引用的舊物件。

驗收使用合成書庫：持續打字超過最大等待、保存期間繼續改字、重試／並行衝突、斷線與磁碟滿、Flutter 單獨 crash、Go 強制終止、各發布步驟中止、尾端與中間損壞、缺基準、超量／循環增量、舊草稿相容、基準換版、有效鎖與失效鎖、重開後預覽／續寫／捨棄，以及正式 VAX 歷史不被自動改動。
