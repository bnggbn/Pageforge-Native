# 個人線索牆、分享與完整副本（規劃）

本合約補充 [段落筆記與線索牆](EVIDENCE_WALL.md) 與 [識別與同步](IDENTITY_SYNC.md)。
「整面帶走」包含主題、卡片、布局與紅線。以下所有權、分享包、匯入、來源證明及更新比較尚未實作；現行 schema v2 仍是每本書的本機布局檔，沒有使用者身分或分享 API。

## 所有權與邊界

線索牆是個人的思考空間。本人建立的筆記、挑選的卡片、卡片位置與紅線由本人管理；共享一本來源書，不等於共享私人筆記或牆。ownerId 表示這份副本的控制者，actorId 表示某次操作的作者；兩者與原始線索作者分開，ID 本身不授予權限。

| 情境 | 預設行為 |
| --- | --- |
| 同一人的不同裝置 | 同步自己的牆與歷史；並行修改保留分支，明確合併 |
| 別人提供新卡片 | 收件者選擇接收；新增自己的筆記／卡片副本，保留來源 |
| 帶走整面線索牆 | 匯入完整指定快照，建立自己的獨立牆，保留主題、布局及紅線 |
| 原分享者修改或刪除 | 不改動已接收的副本；新發布的快照可另外比較、選擇採用 |
| 多人共同改同一面牆 | 非預設功能；未來需另定共享所有權、權限及衝突合約 |

發布者不能藉由分享持續控制收件者的布局或紅線。收件者修改自己的副本，不回寫發布者的牆；這是複製與來源關聯，不是轉移或刪除原牆。預設不訂閱自動覆蓋更新。

## 「整面帶走」的內容

使用者選擇一面牆及版本，分享包包含該快照的主題、名稱、卡片歸屬、筆記內容與引用、畫布幾何、卡片位置／尺寸、紅線端點／標籤，以及原書與版本的來源參照。預設帶走該牆全部主題；日後若提供選擇主題，需明示匯出範圍。

只收集指定快照可達且分享所需的物件，不附上其他牆、未選中的私人筆記、草稿或全部私人 VAX 歷史。原書全文及受保護資產不自動打包；若將來支援另附來源文件，必須另列範圍並確認讀取／分享權限。包內引用文字仍屬分享內容，預覽應讓發布者看見。

每張卡片保留來源文件識別、來源版本 SAI／contentRoot、原文選取位置及引用文字。收件者缺少來源書或相符版本時，仍能閱讀筆記與布局；「回到原文」標記來源未取得，不假造文件 ID、定位或 CFI。內容 hash 相同可驗證 bytes，但不能單獨證明兩份來源文件具有同一邏輯身分。

## ID 與匯入映射

新模型區分 wallId、topicId、cardInstanceId、noteId 及 edgeId：noteId 是筆記身分，cardInstanceId 是該筆記在一個主題中的呈現身分，紅線引用卡片實例。同一筆記出現在不同主題時可有不同位置及紅線。

跨 owner 匯入時重新產生本地 wall／topic／card／edge ID；每個不同的來源筆記只產生一個本地 noteId，再由各主題的卡片引用。原作者、來源 owner、來源 workspace／wall／topic／card／note／edge ID、來源快照及發布者另存不可變 provenance。後續本地修改新增自己的操作作者，不覆寫原始作者資訊。

先建立來源到本地的有型別映射，再重寫卡片歸屬、紅線端點與 activeTopic，整份匯入一起發布。相同文字的兩個不同來源筆記不得僅憑內容 hash 合成同一筆記；實體不可變 blob 可去重，邏輯副本仍各有身分。

匯入是新牆，不與收件者現有的「全部線索」自動合併，也不把其他本地筆記塞進匯入的主題。若分享快照含「全部線索」，它只包含發布時包內的線索；後續新增本地筆記是否加入，須是使用者明確操作，不沿用現行每書自動收集全部筆記的規則。

相同發布者與 bundleId 的相同已驗證 bundleRoot 重送時，預設開啟既有匯入，不重複建卡；「再建立一份副本」才生成另一組本地 ID。相同 bundleId 卻不同 root 視為衝突，不覆蓋已接收記錄。同人的裝置同步保留邏輯 ID；上述重發 ID 僅用於建立獨立副本。

## VAX 與來源證明

分享快照至少承諾 schema、發布者身分／鍵、bundleId、來源 wall／版本參照、分享範圍、筆記 root、布局／主題／卡片／紅線 root 與物件索引。bundleRoot 覆蓋這些有型別欄位及有序／有界依賴；編碼、domain、排序、幾何數值及重複 ID 規則要先定義測試向量。發布簽章綁定 bundleRoot 及用途，發布者公鑰需有明確信任來源。

收件者的正式匯入事件承諾自己的 owner／workspace／wall、revisionId、本地 notesRoot／wallRoot、來源 bundleRoot、發布證明及 ID 映射 root。來源 bundle／事件以 sourceRef 引用；不把別人的來源鏈接成自己的 prevSAI，也不冒充自己的版本父節點。自己的後續版本沿本地來源鏈與個人牆版本圖演進。

分享包可用受信任發布者簽署的獨立快照驗證，不要求攜帶發布者全部私人鏈。此驗證證明指定發布者發布了這份快照及包內資料一致，不能宣稱私人歷史已完整稽核，亦不證明線索敘述屬實。無可驗證作者證明的舊資料只能標示來源自述，不能把欄位中的名字當作已認證作者。

來源書正文有自己的版本與 contentRoot；個人的筆記／牆版本引用指定正文版本，不讓來源書版本收進所有讀者的私人 notesRoot。分享者保留原牆歷史，收件者只接收指定快照及必要證明；私有歷史與選擇性分享分開。

## 匯入及後續更新

Go 負責解析、身分／簽章與內容驗證、來源映射及持久化；Flutter 顯示範圍預覽、缺少來源、衝突及採用選擇，Widget 不直接處理檔案。

匯入前限制總 bytes、物件數、主題／卡片／紅線數、引用／文字長度、解壓後容量、依賴深度與在途驗證量；拒絕路徑穿越、重複身分、越界幾何、不存在／跨主題的紅線端點及未授權 namespace。外部內容預設不執行指令、不自動下載圖片或追蹤來源 URL。

驗證完整分享範圍後顯示預覽；保存所有物件，再原子發布索引／head。失敗不顯示半面牆、不寫入現有牆；超過本地限制時明示原因，不默默截掉卡片或紅線。實作前另定 staging、復原、GC 與設定合約，避免套用現行布局 4 MiB 限制便宣稱能處理任意分享包。

更新只比較另一份明確發布的快照。以首次匯入或上次採用的來源快照為基準，保留原 ID 映射及本地修改；同一筆記、位置或紅線雙邊修改時顯示衝突，由收件者選擇。採用是新的本地版本，刪除亦不抹除舊快照，不用時間戳直接覆蓋。

## 遷移與驗收

現行 schema v2 的 cards 只有 noteId／x／y，edges 以主題內 noteId 為端點；牆沒有 wallId／ownerId／cardInstanceId／provenance，且布局尚無 VAX。新模型需要保留原始位元組備份、定義本地 owner 的首次綁定、ID／端點映射與獨立牆儲存 migration。不得把既有 pageforge:documentId actor 假認證為使用者，也不改寫舊 VAX／筆記／原書。

第一階段先完成個人牆模型及布局版本，再做完整快照匯出／匯入；單卡接收可沿用同一映射與來源合約。同 owner 多裝置同步另行驗收，不以分享包取代同步協定。

驗收至少包含：多主題與跨主題共用筆記的精確往返、布局與紅線保持、缺來源書仍可查閱、不同 owner 的 ID 隔離、重送冪等／另建副本、損壞或缺物件拒絕、超限不截斷、匯入各發布階段中斷、來源證明與映射置換、未認證舊作者、更新與本地修改衝突，以及私人草稿／其他牆／歷史不外洩。
